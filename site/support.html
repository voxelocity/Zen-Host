Something not working?

Search the exact error message you're seeing — most of them are one setting away from fixed. For general questions, try the Q&A instead.

Java

“No Java runtime found” — but I'm sure Java is installed

Zen Host searches, in order: the JAVA_HOME environment variable → /usr/libexec/java_home on macOS → every directory on your PATH → the standard install roots (C:\Program Files\Java, /usr/lib/jvm, /Library/Java/JavaVirtualMachines, Homebrew prefixes and similar).

If it still can't find yours, the install is somewhere non-standard. Point JAVA_HOME at it — the folder that contains bin/java, not the java binary itself:

# macOS / Linux — add to ~/.zshrc or ~/.bashrc export JAVA_HOME=/path/to/jdk-21 # Windows PowerShell (permanent, current user) [Environment]::SetEnvironmentVariable('JAVA_HOME','C:\Program Files\Java\jdk-21','User')

Restart Zen Host afterwards — the runtime is located once at launch.

Java works in my terminal, but Zen Host can't find it

This is the classic macOS and Linux case. A GUI app launched from Finder, the Dock, a .desktop launcher or an AppImage does not inherit your login-shell PATH — anything you exported in ~/.zshrc or ~/.bashrc is invisible to it.

Zen Host works around this by also checking /usr/libexec/java_home and the standard install directories, so a normal JDK install is found regardless. If yours lives somewhere custom, set JAVA_HOME system-wide rather than in a shell rc file, or install a JDK to a standard location.

“Unsupported class file major version” or “has been compiled by a more recent version of the Java Runtime”

Your Java is older than the server jar requires. The number in the message maps to a Java release:

Message saysNeeds JavaTypical Minecraft
major version 5281.16 and older
major version 60161.17
major version 61171.18 – 1.20.4
major version 65211.20.5 and newer

Install Java 21 and the whole range is covered — it runs older servers happily.

“java.lang.OutOfMemoryError: Java heap space”

The server hit its memory ceiling. Raise the RAM allocation for that server, restart, and watch whether it happens again.

If it recurs at 8 GB or more, memory usually isn't the real problem — a misbehaving mod, an enormous view distance, or a runaway entity farm is. Check the console output just before the crash for the mod name.

⚠

Don't assign more RAM than your machine physically has. The JVM will start and then be killed by the OS, which looks like a random crash with no error.

Server won't start

The console prints “[Server process exited with code 1]” and stops

Exit code 1 means the Java process itself refused to continue. Scroll up in the console — the real reason is always printed above the exit line. The usual causes, in order of likelihood:

  1. EULA not accepted (see below)
  2. The port is already in use
  3. A mod failed to load, or a required dependency is missing
  4. Java version too old for that server jar
  5. A corrupt server.properties value, e.g. a non-numeric port
“You need to agree to the EULA in order to run the server”

Mojang requires acceptance before a server will boot. Zen Host shows a prompt on first start — accepting it writes eula=true into eula.txt in the server folder.

If the message keeps coming back, the file isn't being written. Check that the server folder isn't read-only and isn't inside a synced folder (OneDrive, Dropbox, iCloud) that's locking it.

“Failed to bind to port” or “Address already in use”

Something is already listening on that port — nearly always another Minecraft server, or a copy of this one that didn't shut down.

Find it, or just move this server to a free port under Settings → Network → Server Port:

# Windows netstat -ano | findstr :25565 # macOS / Linux lsof -i :25565

The last column on Windows is the process ID, which you can look up in Task Manager's Details tab.

Forge or NeoForge installation failed

These types download an installer jar and run it locally to generate the server, so the failure is usually in that step rather than in Zen Host:

  • No Java on PATH — the installer is itself a Java program.
  • Antivirus interference — the installer writes many files quickly, which some scanners block. Whitelist the server folder.
  • Network interruption — it pulls libraries from Maven repositories while running.
  • That version has no server installer — very old or very new builds sometimes don't.

The last few installer output lines are included in the error message. Delete the half-built server and try again, or pick a neighbouring loader version.

The server says “running” but nothing responds

Zen Host marks a server running when the log prints Minecraft's Done (…)! For help, type "help" line. If it's stuck on starting, the server is still working — first boot generates spawn chunks and can take several minutes on a big modpack.

If it reached running and still doesn't accept connections, the problem is the address or the firewall rather than the server. See the connection section below.

Stopping the server takes ages, or it won't stop at all

Stopping sends the stop command so the world saves cleanly. A big world with many loaded chunks genuinely takes a while to flush.

If it hasn't exited after 15 seconds, Zen Host force-kills the process. A force-kill can lose the last few seconds of unsaved changes, so give it the time it asks for when you can.

Connections

“Tunnel handshake timed out (bore.pub unreachable)”

Zen Host couldn't reach the public relay. It connects to bore.pub on TCP port 7835, which some networks block.

  • On a school, office or campus network, outbound non-standard ports are often firewalled — this is the most common cause.
  • A VPN or strict firewall profile can block it too. Try disabling temporarily to confirm.
  • The public relay is a free community service and is occasionally down.

LAN play keeps working regardless. For a permanent public address, port-forward your router instead and share your own IP.

Friends on my Wi-Fi can't connect to the LAN address

Almost always the host machine's firewall blocking inbound Java connections.

  • Windows — the first launch pops a Windows Defender prompt. If you dismissed it, go to Windows Security → Firewall & network protection → Allow an app, and make sure Java is ticked for Private networks.
  • macOS — System Settings → Network → Firewall → Options, and allow incoming connections for Java.
  • Linux — sudo ufw allow 25565/tcp if ufw is active.

Also check that everyone is genuinely on the same network — "guest" Wi-Fi networks are usually isolated from the main one, and client isolation on some routers blocks device-to-device traffic entirely.

“Failed to verify username” or “Invalid session”

The server has Online Mode on and Mojang's session servers couldn't confirm the player. Usually one of:

  • The player isn't signed in with a genuine Minecraft account.
  • Their client needs restarting to refresh an expired session token.
  • Mojang's authentication servers are having an outage.

Turning online mode off works around it, but then usernames are unverified and anyone can join as anyone — pair it with a whitelist if you do.

“Incompatible FML modded server” / “Mod rejections” on join

The client's mod list doesn't match the server's. Forge and NeoForge compare mods and versions during the handshake and refuse mismatches.

Every player needs the same mods at the same versions on the same loader. The rejection screen lists exactly which mods differ — work through that list. Server-side-only mods are the exception and won't be flagged.

“Connection refused” or “Connection timed out”

Refused means the address was reached but nothing is listening — the server isn't running, or the port is wrong.

Timed out means packets never arrived at all — a firewall is dropping them, or the address is unreachable from where they are.

Confirm the server shows running, then re-copy the address from the Overview tab. Remember the public tunnel port changes on every restart.

“Outdated server” / “Outdated client”

The Minecraft versions don't match. The message tells you which side is behind. Change the version in the Minecraft launcher's installation settings to exactly match your server's version — there is no cross-version compatibility in vanilla Minecraft.

Mods

I added mods and now the server won't boot

Work through these in order — the console names the culprit in nearly every case:

  1. Wrong loader. A Fabric mod on a Forge server (or vice versa) is silently ignored or crashes outright. Bukkit/Spigot plugins never work on modded servers.
  2. Wrong Minecraft version. A 1.20.1 mod will not load on 1.21.
  3. Missing dependency. Most Fabric mods need Fabric API; many mods need a shared library mod.
  4. Client-only mod. Shaders, minimaps and UI mods often crash when loaded server-side. Check the mod page for its required side.

Use the toggle in the Mods tab to disable mods in halves — it renames them to .jar.disabled so the loader skips them — and narrow it down without deleting anything.

Far Render says “No build for Minecraft X yet”

Modrinth has no release of that mod for your exact Minecraft version and loader combination. This is common right after a Minecraft update, and for Voxy, which is Fabric-only.

The other mods still install — each is fetched independently and reported separately. Chunky is the one that actually matters for pre-generation.

Chunky pre-generation seems stuck or never finishes

Pre-generation is genuinely slow — it's generating every chunk in the radius, which for a large radius can take hours and will use most of a CPU core the whole time.

Progress is read from Chunky's own console output, so if the server is lagging badly the percentage updates in bursts rather than smoothly. You can cancel at any time; already-generated chunks are kept, and running it again resumes rather than starting over.

My mods disappeared from the list

The Mods tab lists files in the server's mods folder ending in .jar or .jar.disabled. Anything else — a .zip, or a jar inside a subfolder — isn't shown and won't be loaded by the server either.

Unzip modpack archives before adding them, and keep jars directly in mods rather than nested in folders.

Performance

“Can't keep up! Is the server overloaded?”

The server missed its 20-ticks-per-second budget. Occasional messages during chunk generation are normal; constant ones mean it's genuinely overloaded. In rough order of impact:

  • Drop Simulation Distance to 6–8. This is the single biggest win — it controls how far entities and redstone actually tick.
  • Drop View Distance to 8–10.
  • Switch to Paper, which is substantially faster than vanilla for the same world.
  • Look for entity build-ups — huge mob farms and thousands of dropped items are common culprits.
  • Give it more RAM only if you also see out-of-memory errors.

View distance and simulation distance are separate settings — simulation is the expensive one.

The server lags but my CPU isn't maxed out

Expected. Minecraft's main game loop is effectively single-threaded, so one core saturates while the rest idle — on an 8-core machine that's around 12% total usage at full load.

What matters is single-core speed, not core count. If one core is pinned, the server is CPU-bound no matter what the overall percentage says.

Huge lag spikes every few seconds

Usually garbage-collection pauses or disk I/O:

  • Too much RAM can be worse than too little — a very large heap means longer collection pauses. Try dropping from 12 GB to 6 GB.
  • Mechanical hard drives struggle with chunk saving. An SSD makes a large difference.
  • Antivirus scanning the world folder on every write. Exclude the server directory.
  • Cloud-synced folders — never keep a live world in OneDrive, Dropbox or iCloud Drive.

Install & operating system

macOS: “Zen Host is damaged and can't be opened” or “cannot be opened because the developer cannot be verified”

The builds aren't code-signed with an Apple Developer ID, so Gatekeeper quarantines them. The app is fine — macOS simply can't verify who published it.

Right-click (or Control-click) the app and choose Open, then Open again in the dialog. Double-clicking will not offer that option; the right-click menu is what unlocks it.

If the "damaged" wording appears, clear the quarantine attribute directly:

xattr -dr com.apple.quarantine "/Applications/Zen Host.app"
Windows: “Windows protected your PC” SmartScreen warning

Same cause — the installer isn't signed with a code-signing certificate, so SmartScreen doesn't recognise it yet.

Click More info, then Run anyway. If you'd rather verify first, the installer is built in public by GitHub Actions — the build log for every release is viewable on the repository's Actions tab.

Which Windows or macOS build do I need — x64 or ARM?
  • Windows — Settings → System → About → System type. "ARM-based processor" means arm64; anything else is x64.
  • macOS — Apple menu → About This Mac. An "Apple M1/M2/M3/M4" chip means arm64; "Intel" means x64.

The download section detects this automatically and points the main button at the right file, but every build stays listed if you need a different one.

Linux: the AppImage won't launch

Two things to check. First, it needs the executable bit:

chmod +x "Zen Host-0.1.0-linux-x86_64.AppImage" ./"Zen Host-0.1.0-linux-x86_64.AppImage"

Second, AppImages need FUSE. On Ubuntu 22.04 and newer:

sudo apt install libfuse2

To skip FUSE entirely, run it with --appimage-extract-and-run, or use the .deb or .tar.gz build instead.

Linux: the .deb won't install — dependency errors

dpkg -i doesn't resolve dependencies. Either fix them afterwards or let apt handle it from the start:

sudo apt install ./"Zen Host-0.1.0-linux-amd64.deb" # or, after a failed dpkg -i sudo apt --fix-broken install

On non-Debian distributions (Fedora, Arch, openSUSE) use the AppImage or the .tar.gz — there's no .rpm build.

The app opens to a blank or black window

Usually a GPU driver problem with Electron's hardware acceleration. Launch it once with acceleration off to confirm:

# Windows "%LOCALAPPDATA%\Programs\zen-host\Zen Host.exe" --disable-gpu # macOS "/Applications/Zen Host.app/Contents/MacOS/Zen Host" --disable-gpu # Linux ./"Zen Host-0.1.0-linux-x86_64.AppImage" --disable-gpu

If that fixes it, update your graphics drivers. On Linux, a compositor conflict under Wayland can cause the same thing — try --ozone-platform=x11.

How do I completely uninstall Zen Host?

Removing the app doesn't delete your servers — that's deliberate, so an update never destroys a world. To remove everything, delete the data folder too:

  • Windows — uninstall from Settings → Apps, then delete %APPDATA%\zen-host
  • macOS — drag the app to the Trash, then delete ~/Library/Application Support/zen-host
  • Linux — sudo apt remove zen-host (or delete the AppImage), then ~/.config/zen-host
⚠

That data folder contains every world you've created. Copy anything you want to keep before deleting it.

Files & data

Where are the logs when I need to report a bug?

Minecraft writes its own logs inside each server's folder, which is what you'll want for a crash:

  • logs/latest.log — the most recent run
  • crash-reports/ — written when the server crashes outright

Open the server folder from the Overview tab to get to them. When filing an issue on GitHub, attach latest.log along with your OS, Zen Host version, server type and Minecraft version.

A setting I changed didn't take effect

server.properties is read by Minecraft once at startup, so changes need a server restart. The exceptions are things applied through commands — operator changes are issued live, for instance.

Note also that world-generation settings (seed, world type, structures) only affect terrain that hasn't been generated yet. Changing the seed of an existing world does nothing.

My world is corrupted or won't load

Usually a region file damaged by a force-kill, a power cut, or cloud-sync software writing underneath the server.

  1. Stop the server and take a copy of the whole world folder before touching anything.
  2. Delete world/session.lock — a stale lock alone can block loading, and it's regenerated automatically.
  3. If a specific region is broken, the console names the file. Deleting that .mca file regenerates that area as fresh terrain and loses whatever was built there.
  4. level.dat_old is an automatic backup of level.dat — renaming it over the broken one sometimes recovers world metadata.
Can I move a server to another computer?

Yes. Install Zen Host on the new machine, create a server of the same type and Minecraft version, stop it, then copy the old server's world folder, server.properties, ops.json and mods folder into the new server's folder.

Copying the whole folder verbatim won't work on its own, because Zen Host tracks servers by an internal ID in its own index file.

Does updating Zen Host affect my servers?

No. Servers live in the user-data directory, which installers don't touch — updating in place keeps every world, mod and setting.

Backing up that folder before a major update is still cheap insurance.

Nothing matched that search

Try a shorter phrase or a single keyword — searching “port” or “java” catches more than a full error message. You can also open an issue on GitHub.

Still not solved?

Open an issue with your latest.log, OS and server type — that's usually enough to pin it down.
