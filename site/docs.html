Installation

Zen Host runs on Windows, macOS and Linux, on both 64-bit Intel/AMD and ARM. Pick the format for your platform from the download section.

Windows

Run the .exe installer. It lets you choose an install directory and creates Start-menu and desktop shortcuts. The .zip is a portable build — extract it anywhere and run Zen Host.exe, no installation.

Builds are unsigned, so SmartScreen shows a warning on first run. Click More info → Run anyway.

macOS

Open the .dmg and drag Zen Host to Applications. Take the arm64 build for Apple Silicon (M1 and later) or x64 for Intel Macs.

Because the app isn't notarized, the first launch needs a right-click → Open → Open. Double-clicking won't offer that option.

ℹ

If macOS claims the app is "damaged", clear the quarantine flag: xattr -dr com.apple.quarantine "/Applications/Zen Host.app"

Linux

Three formats, all built for x64 and arm64:

  • AppImage — runs on any distribution. Needs the executable bit and FUSE.
  • .deb — for Debian, Ubuntu and derivatives.
  • .tar.gz — extract and run the zen-host binary.
# AppImage chmod +x "Zen Host-0.1.0-linux-x86_64.AppImage" ./"Zen Host-0.1.0-linux-x86_64.AppImage" # Debian package (apt resolves dependencies; dpkg -i does not) sudo apt install ./"Zen Host-0.1.0-linux-amd64.deb"

Installing Java

Zen Host bundles everything it needs to run itself, but a Minecraft server is a Java program — so a JDK has to be installed separately.

Install Java 21. Minecraft 1.20.5 and newer require it, and it runs older versions fine.

PlatformCommand / source
Windowsadoptium.net installer
macOSbrew install --cask temurin
Debian / Ubuntusudo apt install openjdk-21-jre-headless
Fedorasudo dnf install java-21-openjdk-headless
Archsudo pacman -S jre21-openjdk-headless

How Zen Host finds it

A GUI app launched from Finder, a .desktop launcher or an AppImage does not inherit your login-shell PATH, so looking only there would fail exactly when the app isn't started from a terminal. Zen Host searches, in order:

  1. The JAVA_HOME environment variable
  2. /usr/libexec/java_home on macOS
  3. Every directory on PATH
  4. Standard install roots — C:\Program Files\Java, /usr/lib/jvm, /Library/Java/JavaVirtualMachines, Homebrew prefixes and similar, newest version first

If your JDK lives somewhere unusual, set JAVA_HOME to the folder containing bin/java and restart the app.

Your first server

  1. Create. Give it a name, choose a type and a Minecraft version, and set how much RAM it gets. Version lists are fetched live from Mojang, PaperMC and the loader APIs.
  2. Wait for the download. Vanilla, Paper and Fabric pull a server jar directly. Forge and NeoForge download an installer and run it locally, which takes longer and prints its progress.
  3. Accept the EULA. Mojang requires it; accepting writes eula=true to eula.txt.
  4. Start. First boot generates the spawn area, so it takes longer than later ones. The server is marked running once Minecraft prints its Done line.
  5. Connect. Copy an address from the Overview tab and join from Minecraft with the matching version.
✓

New servers start with a sensible server.properties — survival, normal difficulty, 20 players, view and simulation distance 10, port 25565.

How each type is launched

Vanilla, Paper, Fabric and older Forge builds run a single server jar. Modern Forge and NeoForge (Minecraft 1.17+) instead generate an argument file during installation, and Zen Host launches through that — picking win_args.txt or unix_args.txt to match your platform.

# jar-based types java -Xms<min>M -Xmx<max>M -jar server.jar nogui # modern Forge / NeoForge java -Xms<min>M -Xmx<max>M @libraries/.../unix_args.txt nogui

Memory & performance

The RAM value you set becomes the JVM's maximum heap. The starting heap is set to the same value or 1 GB, whichever is smaller, so the server doesn't reserve everything up front.

SetupSuggested RAM
Vanilla or Paper, 1–5 players2 GB
Paper with plugins, 5–15 players4 GB
Small mod set (10–40 mods)4–6 GB
Large modpack (150+ mods)8 GB+

Never assign more than your machine physically has — the JVM will start and then be killed by the OS. Beyond about 8 GB, extra heap can make garbage-collection pauses worse rather than better.

If the server can't keep up

Minecraft's game loop is effectively single-threaded, so one CPU core saturating while the others idle is normal and expected. In order of impact:

  • Lower Simulation Distance to 6–8 — the single biggest win, since it controls how far entities and redstone actually tick.
  • Lower View Distance to 8–10.
  • Switch to Paper, which is substantially faster than vanilla on the same world.
  • Keep the world off mechanical drives and out of cloud-synced folders.

Mods & plugins

Drag .jar files onto the Mods tab, or use the browse button. They're copied into the server's mods folder; restart for changes to apply.

Disabling a mod renames it to .jar.disabled, which loaders skip — useful for bisecting a broken mod list without deleting anything. Only files ending .jar or .jar.disabled directly inside mods are listed, so unzip packs first and don't nest jars in subfolders.

Getting mods right

  • Match the Minecraft version exactly.
  • Match the loader — Fabric, Forge and NeoForge builds are not interchangeable.
  • Install dependencies. Most Fabric mods need Fabric API.
  • Check which side a mod is for. Client-only mods (shaders, minimaps) often crash a server.
  • Every player needs the same mods at the same versions, except server-side-only ones.

Modrinth and CurseForge are the standard sources.

Paper plugins

Paper loads Bukkit/Spigot plugins from a plugins folder rather than mods. Open the server folder from the Overview tab and drop them in there manually.

Operators

Add a player by username on the Operators tab. Zen Host resolves their UUID and writes ops.json — so it works whether the server is running or stopped, and the entry survives a rename.

UUID resolution follows the server's Online Mode setting. In online mode the real Mojang UUID is looked up, and an unknown username is rejected. In offline mode the same deterministic offline UUID Minecraft itself uses is generated locally.

LevelGrants
1Bypass spawn protection
2Single-player cheats — /gamemode, /give, /tp, command blocks
3Player management — /kick, /ban, /op
4Everything, including /stop

New operators default to level 4. If the server is running, the op command is issued immediately so it applies without a restart.

Far render

Installs the server-side half of an extended-view-distance setup, fetching builds that match your server's Minecraft version and loader from Modrinth:

  • Distant Horizons — level-of-detail terrain well beyond normal view distance. Fabric, Forge and NeoForge.
  • Voxy — a similar LOD renderer. Fabric only.
  • Chunky — pre-generates chunks so distant terrain already exists on disk.

Each mod is fetched independently and reported separately, so one missing build doesn't block the others. If Modrinth has no release for your exact version and loader, you'll be told which mod and why.

Pre-generating chunks

With the server running, choose a radius in blocks and start. Zen Host drives Chunky through the console and reads progress back out of its output:

chunky radius <blocks> chunky start

This is slow by nature — it generates every chunk in the radius and will use most of a CPU core throughout. Cancelling keeps everything already generated, and running it again resumes rather than restarting.

ℹ

Players still need the matching client mod to see the extra distance. The server side only supplies the data.

Networking

The Overview tab shows up to three addresses, each with a copy button.

The public tunnel

Marking a server public opens a tunnel to the free bore.pub relay, giving you an internet-reachable address with no port forwarding, firewall rules or dynamic DNS. It's implemented as a pure-Node client speaking the bore protocol on TCP port 7835 — no extra binary is bundled or downloaded.

⚠

The relay assigns a random port each time the server starts, so the public address changes on every restart. Port-forward your own router if you need a permanent one.

The tunnel reconnects automatically if it drops. If the handshake times out, outbound port 7835 is most likely blocked — common on school, office and campus networks.

Firewalls

LAN play needs inbound connections allowed to Java on the host machine. Windows prompts on first launch; if it was dismissed, re-allow Java for Private networks under Windows Security. On Linux with ufw active, sudo ufw allow 25565/tcp.

Files & backups

Every server lives in its own folder under the app's user-data directory:

PlatformLocation
Windows%APPDATA%\zen-host\servers\<id>\
macOS~/Library/Application Support/zen-host/servers/<id>/
Linux~/.config/zen-host/servers/<id>/

Inside is an ordinary Minecraft server, so any standard Minecraft tooling works on it:

PathContents
world/The entire save — terrain, inventories, player data
server.propertiesServer configuration
ops.jsonOperators
mods/Mod jars (modded types)
plugins/Plugin jars (Paper)
logs/latest.logMost recent run's log
crash-reports/Written on a hard crash
eula.txtMojang EULA acceptance

Backing up

Stop the server first, then copy the world folder. Copying it live risks catching a half-written region file. To restore, drop the folder back in place of the current one while the server is stopped.

⚠

Deleting a server removes its whole folder, world included, with no undo. Never keep a live world in OneDrive, Dropbox or iCloud Drive — sync clients write underneath the server and corrupt region files.

Building from source

Zen Host is an Electron app with no build step for the front end — the source is what ships.

git clone https://github.com/voxelocity/Zen-Host.git cd Zen-Host npm install npm start

Packaging

npm run dist:win # Windows x64 + arm64 npm run dist:mac # macOS x64 + arm64 npm run dist:linux # Linux x64 + arm64

Output lands in dist/. Icons are generated from build/zenlogo.png by npm run icons.

ℹ

Cross-compiling has hard limits: macOS .dmg builds require macOS, Linux .deb requires fpm, and .AppImage requires symlink privileges. From Windows you can build every Windows target plus the Linux .tar.gz. The GitHub Actions workflow builds all of them on native runners, and pushing a v* tag publishes a release.
